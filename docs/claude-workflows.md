# Claude Code workflows

This project ships its own Claude Code setup so daily work follows the same steps every time, and so the steps can be improved over time.

## What's where

| Path                          | Purpose                                                             |
| ----------------------------- | ------------------------------------------------------------------- |
| `CLAUDE.md`                   | Project map, commands, conventions, definition of done (always loaded) |
| `backend/CLAUDE.md`, `frontend/CLAUDE.md` | Area rules, loaded when Claude works in that folder     |
| `.claude/skills/<name>/SKILL.md` | The workflows, invoked as `/<name>`                               |
| `.claude/skills/speckit-*/`   | Spec Kit skills, generated by `specify init` (don't hand-edit)      |
| `.specify/memory/constitution.md` | Project principles every spec/plan is checked against          |
| `.specify/`                   | Spec Kit templates, scripts, extensions (git), workflow (managed by the CLI) |
| `.claude/settings.json`       | Shared permissions: safe commands auto-allowed, risky ones ask, `.env` and volume deletion denied |
| `.claude/settings.local.json` | Your personal overrides (git-ignored)                               |
| `docs/backlog.md`             | Work queue the workflows read and update                            |
| `specs/NNN-<slug>/`           | One folder per feature: spec, plan, research, data model, contracts, tasks, checklists |
| `docs/dev-log/`               | One file per day, written by `/daily-wrap-up`                       |

## A typical day

```text
/daily-start                         → status report + suggested focus
/feature streaming chat replies      → Spec Kit: specify ⏸ → clarify → plan ⏸ → tasks + analyze ⏸ → implement → converge → /verify ⏸
/bugfix "502 when message has emoji" → failing test → fix → verify
/verify                              → pass/fail table of every gate
/daily-wrap-up                       → dev log, backlog, commit messages
```

`daily-start`, `daily-wrap-up` and `improve-workflow` are user-invoked only (`disable-model-invocation: true`). Claude can pick `feature`, `bugfix` and `verify` on its own when the request matches.

## Spec-driven development with Spec Kit

[GitHub Spec Kit](https://github.com/github/spec-kit) is installed with the Claude integration (skills mode), bash scripts, and the bundled `git` extension.

| Step | Skill | Output in `specs/NNN-<slug>/` |
| ---- | ----- | ----------------------------- |
| Principles (once, then amend) | `/speckit-constitution` | `.specify/memory/constitution.md` |
| What and why | `/speckit-specify <description>` | `spec.md`, `checklists/requirements.md`, new `NNN-<slug>` branch |
| Remove ambiguity (optional) | `/speckit-clarify` | updates `spec.md` |
| How (stack, design) | `/speckit-plan <stack notes>` | `plan.md`, `research.md`, `data-model.md`, `contracts/`, `quickstart.md` |
| Requirement quality (optional) | `/speckit-checklist <focus>` | `checklists/<focus>.md` |
| Work breakdown | `/speckit-tasks` | `tasks.md` |
| Consistency check (optional, read-only) | `/speckit-analyze` | report only |
| Build | `/speckit-implement` | code + ticked `tasks.md` |
| Close gaps | `/speckit-converge` | appends tasks until "Converged" |

- `/feature` wraps this sequence with checkpoints plus the backlog, Docker E2E, and `/verify` steps. Use the individual skills when you only want one step, such as re-planning.
- **Spec lifecycle:** each `specs/NNN-*` folder is the record of that change. Later changes to the same area get a new spec that references the old one.
- **Git extension:** `/speckit-specify` creates the feature branch. Branch naming and the auto-commit hooks (all off) are configured in `.specify/extensions/git/git-config.yml`. Switching branches doesn't switch the active feature; that's tracked in `.specify/feature.json`.
- **Changing the rules:** amend principles with `/speckit-constitution <change>` (it bumps the version), then align `CLAUDE.md`. To change templates, use a preset or override rather than editing `.specify/templates/`, which `specify init` refreshes.
- **Upgrading Spec Kit:**
  1. Run `specify self check` to see whether a newer version exists.
  2. Run `uv tool install specify-cli --force --from git+https://github.com/github/spec-kit.git@vX.Y.Z`.
  3. Re-run `specify init --here --force --integration claude --script sh --ignore-agent-tools` on a clean working tree and review the diff. The constitution and `specs/` are preserved.
  4. Add a line to the Changelog below. `.specify/init-options.json` records the installed version.

## Improving the workflows

- Run `/improve-workflow <what went wrong>`. It reads recent dev-log "Problems & learnings", proposes changes, and applies them after you approve.
- Rules of thumb:
  - A **fact or convention** goes in a `CLAUDE.md`.
  - A **multi-step procedure** goes in a skill.
  - Something that **must always happen** (format on save, block a path) goes in a hook in `.claude/settings.json`; instructions can be skipped, hooks can't.
- Keep skills short and imperative. Add ⏸ checkpoints where you want to review before Claude continues.
- To add a skill: create `.claude/skills/<name>/SKILL.md` with frontmatter `name`, `description` (say *when* to use it), and optionally `argument-hint` and `disable-model-invocation`. Then add it to the table in `CLAUDE.md`.
